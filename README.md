# Сховище

Персональний сайт-каталог моїх проєктів: українізатори, моди, доповнення та інструменти для відеоігор. Це статичний сайт (HTML + CSS + JavaScript) без збирання й встановлення програм; він працює на безкоштовному GitHub Pages.

> Усі проєкти в каталозі зараз — **приклади** з позначкою «Приклад — замінити своїми даними». Замініть їх своїми.

**Керування проєктами через адмін-панель** (`/admin/`, вхід лише для адміністратора, дані в Supabase): налаштування та користування описано в **[ADMIN_SETUP.md](ADMIN_SETUP.md)**.

**Без Supabase** проєкти можна вести у файлі `data/projects.js`: див. [ADDING_PROJECTS.md](ADDING_PROJECTS.md) (шаблони записів, інструкції). Поки в `data/supabase-config.js` не вказано параметри Supabase, сайт показує саме цей файл.

## З яких файлів складається сайт

```
index.html                ← сторінка (структура). Зазвичай не чіпати
css/style.css             ← вигляд (кольори, картки, галерея)
js/app.js                 ← логіка: пошук, фільтри, сторінка проєкту, галерея. Зазвичай не чіпати
data/site.js              ← ✏️ назва сайту, ваш GitHub, текст «Про автора»
data/projects.js          ← ✏️ запасний список проєктів (використовується, поки не підключено Supabase)
data/supabase-config.js   ← ✏️ публічні параметри Supabase (URL та publishable key)
js/view.js                ← спільний код відображення карток і сторінок проєктів
admin/                    ← адмін-панель (index.html, admin.js, admin.css, supabase-lite.js)
supabase/migrations/      ← SQL: таблиці, безпека (RLS), файли, імпорт наявних проєктів
tests/                    ← перевірки безпеки (rls_test.sql, live_api_check.mjs, local/)
ADMIN_SETUP.md            ← налаштування Supabase та користування адмін-панеллю
images/placeholder.svg    ← заглушка, коли немає зображення
images/projects/<id>/     ← ✏️ обкладинки й скриншоти кожного проєкту
ADDING_PROJECTS.md        ← інструкції та шаблони
.nojekyll                 ← службовий файл для GitHub Pages
```

Дані лежать у `.js`-файлах (а не в `.json`), бо так сайт відкривається подвійним кліком без сервера.

## Як змінити назву сайту та посилання на GitHub

Відкрийте `data/site.js` і змініть текст у лапках:

- `title` — назва сайту (зараз «Сховище»);
- `githubUsername` — ім'я користувача на GitHub (зараз `introyema`; перевірте, що воно правильне; порожнє значення `""` прибере кнопки GitHub);
- `tagline` — підзаголовок на головному екрані;
- `about` — текст «Про автора» (кожен рядок — окремий абзац);
- `copyrightNote` — примітка про права внизу сторінки.

Назва також є в `<title>` та метаданих `index.html` (для вкладки браузера та пошукових систем).

## Категорії

`ukrainizer` (Українізатори), `mod` (Моди), `addon` (Доповнення), `tool` (Інструменти), `other` (Інше; фільтр з'являється, лише коли є такі проєкти). Окремої категорії «Переклади» немає: переклади ігор — це українізатори. Старе значення `translation` автоматично вважається `ukrainizer`.

## Як переглянути сайт на своєму комп'ютері

Двічі клацніть на `index.html`. Після змін оновіть сторінку (F5).

## Як опублікувати через GitHub Pages

Репозиторій: `https://github.com/introyema/warehouse`.

1. Завантажте файли на GitHub (Add file → Upload files → Commit changes).
2. Відкрийте **Settings** → **Pages**.
3. **Source**: Deploy from a branch.
4. **Branch**: `main`, папка `/ (root)`, натисніть **Save**.
5. Через 1–3 хвилини сайт з'явиться за адресою `https://introyema.github.io/warehouse/`.

Усі шляхи на сайті відносні, тому він працює й у підпапці `/warehouse/`.

## Як оновлювати сайт

Відкрийте файл на github.com → значок олівця (Edit) → внесіть зміни → **Commit changes**. Сайт оновиться за 1–3 хвилини. Докладніше див. розділ «Г» у [ADDING_PROJECTS.md](ADDING_PROJECTS.md).

## Права на матеріали

Не кладіть у репозиторій файли ігор, чужі ресурси чи зображення без дозволу. Архіви з модами та українізаторами краще розміщувати окремо (GitHub Releases або інший хостинг), а в каталозі лише вказувати посилання.
