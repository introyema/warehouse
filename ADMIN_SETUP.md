# Адмін-панель «Сховища»: налаштування та користування

Через адмін-панель (`/admin/`) ви додаєте, редагуєте, публікуєте й видаляєте проєкти, завантажуєте обкладинки, скриншоти та архіви **без редагування коду**. Дані зберігаються в Supabase (безкоштовний хмарний сервіс), а сам сайт, як і раніше, лежить на GitHub Pages.

## Як це працює (простими словами)

```
Відвідувач ──► сайт на GitHub Pages ──► читає ОПУБЛІКОВАНІ проєкти з Supabase
Ви ──► /admin/ ──► вхід (пошта + пароль) ──► Supabase перевіряє, що ви в списку адміністраторів
                                         ──► лише тоді дозволяє створювати / змінювати / видаляти
```

- **Захист — на боці Supabase.** База має правила (RLS), за якими запис дозволений тільки обліковому запису з приватного списку `admins`. Навіть якщо хтось дізнається адресу `/admin/` чи відправить запит напряму до API, без ваших прав записати нічого не вдасться.
- Кнопки керування видно лише на сторінці `/admin/` після входу. На сайті для відвідувачів їх немає, посилання на `/admin/` ніде не вказане.
- У коді сайту є лише **публічний** ключ Supabase (він призначений для браузера і безпечний лише разом із цими правилами). Секретний ключ `service_role` не використовується **ніде** і не повинен потрапляти в репозиторій.

## Що зроблено автоматично, а що потрібно зробити вам

**Уже зроблено в коді (Claude Code):** адмін-панель, вхід, форма проєкту, завантаження зображень і архівів, попередній перегляд, публічний каталог з Supabase, SQL-міграції та політики безпеки, автоматичні перевірки, ця документація.

**Потрібно зробити вам (потрібен ваш акаунт і пароль, їх я не можу створити за вас):**

1. створити проєкт Supabase;
2. вимкнути самореєстрацію;
3. створити свій обліковий запис адміністратора;
4. виконати SQL-міграції;
5. додати свій ідентифікатор до списку адміністраторів;
6. вписати публічні параметри підключення у `data/supabase-config.js`;
7. запустити перевірки безпеки.

Нікому не надсилайте і не вставляйте в код свій пароль чи ключ `service_role`.

---

## Крок 1. Створіть проєкт Supabase

1. Відкрийте <https://supabase.com> і увійдіть (можна через GitHub).
2. Натисніть **New project**. Обрати організацію, ввести **Name** (напр. `skhovyshche`), **Database Password** (придумайте надійний і збережіть у менеджері паролів; у сайт він не вводиться), **Region** (найближчий до вас, напр. Frankfurt).
3. Натисніть **Create new project** і зачекайте 1–2 хвилини.

## Крок 2. Вимкніть самореєстрацію

1. Меню ліворуч: **Authentication** → **Sign In / Providers** (у старому інтерфейсі: **Authentication → Providers** або **Settings**).
2. Знайдіть перемикач **Allow new users to sign up** і **вимкніть** його. Збережіть (**Save**).
3. Блок **Email** має лишатися увімкненим (він потрібен для входу за поштою й паролем).

Навіть якщо цей перемикач залишити увімкненим, сторонні користувачі не зможуть нічого змінювати (їх немає в списку адміністраторів), але краще вимкнути.

## Крок 3. Створіть свій обліковий запис адміністратора

1. **Authentication** → **Users** → **Add user** → **Create new user**.
2. Введіть свою пошту та надійний пароль, увімкніть **Auto Confirm User**, натисніть **Create user**.
3. У списку користувачів скопіюйте значення **User UID** (довгий код на кшталт `a1b2c3d4-…`). Воно знадобиться в кроці 5.

На сайті реєстрації адміністраторів немає, лише так.

## Крок 4. Виконайте SQL-міграції

1. Меню ліворуч: **SQL Editor** → **New query**.
2. Відкрийте файл `supabase/migrations/001_schema_and_security.sql` (у вашому репозиторії), скопіюйте весь текст, вставте в редактор і натисніть **Run**. Має з'явитися «Success. No rows returned».
3. Створіть ще один запит (**New query**), вставте вміст `supabase/migrations/002_import_existing_projects.sql` і натисніть **Run**. Це перенесе наявні 6 проєктів (приклади) у базу. Ці файли можна запускати повторно без шкоди.

Міграція створює: таблицю `projects`, приватну таблицю `admins`, функцію `is_admin()`, правила RLS, бакети **project-media** (зображення до 5 МБ) та **project-files** (архіви до 50 МБ) і політики доступу до файлів.

## Крок 5. Додайте себе до списку адміністраторів

У **SQL Editor** створіть новий запит і виконайте (замініть `ВАШ-USER-UID` на код із кроку 3, залишивши лапки):

```sql
insert into public.admins (user_id) values ('ВАШ-USER-UID');
```

Лише цей один рядок надає права адміністратора. Користувач сам собі додати рядок не може: таблиця `admins` закрита від API.

## Крок 6. Вкажіть публічні параметри підключення

1. У Supabase: **Project Settings** (значок шестерні) → **API** (або кнопка **Connect** вгорі).
2. Скопіюйте **Project URL** (вигляд `https://xxxx.supabase.co`) і **Publishable key** (починається з `sb_publishable_…`; у старих проєктах це ключ `anon` `public`).
3. Відкрийте файл `data/supabase-config.js` і вставте значення:

```js
window.SUPABASE_CONFIG = {
  url: "https://xxxx.supabase.co",
  anonKey: "sb_publishable_..."
};
```

⚠️ Ключі **secret** і **service_role** сюди вставляти **заборонено**.

Після цього завантажте змінені файли на GitHub (див. `README.md`, розділ «Як оновлювати сайт»). Через 1–3 хвилини:

- сайт читатиме проєкти з Supabase;
- адмін-панель буде за адресою `https://introyema.github.io/warehouse/admin/`.

(Поки `url` порожній, сайт показує проєкти з `data/projects.js`, а адмін-панель повідомляє, що не налаштована.)

## Крок 7. Перевірте безпеку на своєму проєкті

**Перевірка 1 — правила бази.** У **SQL Editor** вставте весь файл `tests/rls_test.sql` і натисніть **Run**. Унизу з'явиться таблиця. У **всіх** рядків має бути `ok = true`. Скрипт сам створює й видаляє тестові дані та користувачів.

**Перевірка 2 — зовнішній API** (потрібен Node.js 18+). У PowerShell у папці сайту:

```powershell
$env:SUPABASE_URL="https://xxxx.supabase.co"
$env:SUPABASE_ANON_KEY="sb_publishable_..."
node tests/live_api_check.mjs
```

Усі рядки мають бути `OK`. За бажанням створіть у **Authentication → Users** другого, звичайного користувача (не додавайте його до `admins`) і додайте `$env:USER_EMAIL="..."; $env:USER_PASSWORD="..."` перед запуском. Тоді буде перевірено й цей сценарій.

**Перевірка 3 — вручну.**
- Відкрийте сайт у вікні інкогніто: немає жодних кнопок редагування, чернеток не видно.
- Відкрийте `/admin/` в інкогніто: видно лише форму входу.
- Увійдіть: має відкритися панель.

## Як користуватися адмін-панеллю

Відкрийте `https://introyema.github.io/warehouse/admin/` → введіть пошту й пароль → **Увійти**. Кнопка **Вийти** вгорі завершує сесію.

Розділи: **Головна** (кількість проєктів, останні зміни), **Проєкти** (таблиця з пошуком і фільтрами; кнопки «Редагувати», «Переглянути», «Опублікувати / Зняти з публікації», «Видалити» із підтвердженням), **Додати проєкт**.

Статуси: **Чернетка** — бачите тільки ви; **Опубліковано** — бачать усі; **Архівний** — видно відвідувачам із позначкою «Архівний».

### Додати українізатор Million Depth

1. **Додати проєкт**. Категорія **Українізатор** (вона вже обрана).
2. Назва: `Український переклад Million Depth`, гра: `Million Depth`. Адреса (slug) заповниться сама (її можна змінити).
3. Короткий опис (обов'язковий для публікації) і повний опис: що перекладено і в якому стані.
4. Версія, дата оновлення, сумісність: вписуйте лише те, що справді перевірили. Особливості перекладу: по одному на рядок. Інструкція зі встановлення: кожен крок з нового рядка.
5. **Обкладинка**: оберіть файл JPG/PNG/WebP (бажано 16:9, до 5 МБ). З'явиться попередній перегляд.
6. **Скриншоти**: оберіть кілька файлів. Знімайте саме результат перекладу: меню, діалоги, інтерфейс гри. Для кожного вкажіть підпис і альтернативний текст (опис для людей, які не бачать картинку). Порядок змінюють кнопки «↑ Вище» / «↓ Нижче», видаляє «Видалити».
7. **Завантаження** (оберіть один спосіб):
   - **Завантажити архів на сайт**: `.zip`, `.7z` або `.rar` до 50 МБ;
   - **Зовнішнє посилання**: якщо архів більший або ви хочете GitHub Releases. Завантажте архів у Releases (сторінка репозиторію → **Releases** → **Create a new release** → додайте файл → **Publish release**), правою кнопкою на файлі скопіюйте адресу посилання й вставте.
8. **Вихідний код або сторінка проєкту** вказується окремо від завантаження.
9. **Попередній перегляд**: перегляньте картку й повну сторінку (даних ще ніхто не бачить).
10. **Опублікувати**. Проєкт одразу з'явиться на сайті. Якщо щось не заповнено, під полем буде зрозуміла помилка, а введені дані залишаться.

Приклад Million Depth, що вже є в каталозі (з позначкою «Приклад»), можна відкрити через **Редагувати** і замінити своїми даними. Пам'ятайте зняти галочку «Це приклад».

### Додати мод для іншої гри

Те саме, але категорія **Мод**. Тоді з'являться додаткові поля: «Що змінює мод», «Необхідні залежності», «Можливі конфлікти». У скриншотах покажіть роботу мода в грі. Назву гри вкажіть у полі «Назва гри».

### Змінити проєкт або зняти з публікації

- **Змінити:** **Проєкти** → «Редагувати» → внесіть зміни → **Зберегти зміни**. Заміна обкладинки чи файлу: завантажте новий, старий видаляється лише після успішного збереження.
- **Зняти з публікації:** у таблиці натисніть «Зняти з публікації» (проєкт стане чернеткою, залишиться в панелі). Повернути: «Опублікувати».
- **Видалити:** «Видалити» → підтвердьте. Це видаляє і запис, і завантажені файли.

## Важливі застереження

- **Файли чернеток.** Бакети публічні для читання: щоб відвідувачі могли дивитися скриншоти й завантажувати файли. Адреси файлів містять довгі випадкові коди, але технічно той, хто знає точну адресу файлу чернетки, може його відкрити. Для секретних матеріалів не користуйтеся завантаженням.
- **Ліміти.** Безкоштовний план Supabase обмежує розмір файлу 50 МБ, а сховище та трафік загалом. Для великих архівів використовуйте GitHub Releases.
- **Сон проєкту.** Безкоштовні проєкти Supabase можуть призупинятися після тривалої неактивності (відновлення в Dashboard кнопкою **Restore**). Поки проєкт спить, сайт показує запасні дані з `data/projects.js` (приклади), а не ваші проєкти. Після переходу на Supabase можна очистити список у `data/projects.js` (залишити `window.PROJECTS = [];`).
- **Втрата доступу.** Створіть нового користувача (крок 3) і додайте його UID у `admins` (крок 5). Прибрати адміністратора: `delete from public.admins where user_id = '...';`
- **Скасований вхід.** Токен сесії зберігається в браузері. На чужому комп'ютері обов'язково натисніть «Вийти».

## Що перевірено, а що ні

| Перевірка | Стан |
|---|---|
| SQL-міграції виконуються й повторно запускаються без помилок | ✅ перевірено локально (вбудований PostgreSQL, `tests/local`) |
| 40 перевірок RLS (анонім, звичайний користувач, `user_metadata`, адміністратор, Storage) | ✅ пройдено локально; послаблення політик їх провалює |
| Інтерфейс: вхід, відмова неадміністратору, створення, завантаження, публікація, зняття, видалення | ✅ перевірено в браузері на імітації Supabase |
| Робота з **вашим** проєктом Supabase (реальні Auth, Storage, ліміти) | ⏳ потребує ваших кроків 1–6 і перевірок кроку 7 |
| Публічний каталог із реальної бази | ⏳ після кроку 6 |

Локальна перевірка використовує імітацію Supabase, а не справжній сервіс, тому перевірки з кроку 7 обов'язкові.
